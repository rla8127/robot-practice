# 01. 빌드 과정과 가상 모터 — 학습 노트

> 1주 차 첫 세션. `main.cpp`, `motor.h`, `motor.cpp`를 한 줄씩 읽고,
> "빌드"가 무엇인지 이해한 뒤, 모터에 안전 범위를 직접 추가해 본다.

---

## 1. 우리가 만든 건 "가상 모터" 한 개

이 폴더에는 파일이 세 개 있다.

- `motor.h` : "Motor라는 게 있고, 이런 기능이 있다"고 **소개**하는 파일
- `motor.cpp` : 그 기능들이 **실제로 어떻게 동작하는지** 적은 파일
- `main.cpp` : 모터를 **실제로 써 보는** 파일 (프로그램 시작점)

비유하면 `motor.h`는 식당 메뉴판, `motor.cpp`는 주방 레시피, `main.cpp`는 손님이다.
손님은 메뉴판만 보고 주문하고, 레시피를 알 필요가 없다. 이것이 C++이 파일을 나누는 이유다.

## 2. motor.h 한 줄씩 읽기

```cpp
#pragma once
```
"이 파일을 한 프로그램에서 두 번 읽게 되더라도 한 번만 읽어라"라는 뜻.
지금은 헤더 파일 맨 위에 늘 쓰는 주문 정도로 기억하면 된다.

```cpp
class Motor {
public:
```
Motor라는 **새로운 자료형**을 만든다. `int`나 `double`처럼 이제 `Motor`라는 타입을 쓸 수 있다.
`public:` 아래는 밖에서 자유롭게 쓸 수 있는 부분이다.

```cpp
    explicit Motor(int id);
```
**생성자**. `Motor motor(1);` 처럼 모터를 만들 때 자동으로 호출된다.
1번 모터, 2번 모터처럼 번호를 받는다. `explicit`는 지금은 "항상 붙이는 게 안전하다" 정도만 알면 된다.

```cpp
    void moveTo(double target);
    void update();
```
- `moveTo(3.5)` : "3.5 위치로 가라"고 **목표만** 알려 준다. 아직 움직이지는 않는다.
- `update()` : 한 번 부를 때마다 **한 걸음** 움직인다.

실제 장비도 이렇게 동작한다. 목표를 주면 순간이동하는 게 아니라, 제어 프로그램이 아주 짧은 주기(예: 1ms)마다
"조금 더, 조금 더" 하며 움직이게 한다. `update()`가 그 "한 주기"를 흉내 낸 것이다.

```cpp
    bool isArrived() const;
    double position() const;
    int id() const;
```
상태를 **물어보는** 함수들. 도착했니? 지금 어디니? 몇 번 모터니?
뒤에 붙은 `const`는 "이 함수는 물어보기만 하고 모터 상태를 바꾸지 않는다"는 약속이다.

```cpp
private:
    int id_;
    double position_ = 0.0;
    double target_ = 0.0;
    static constexpr double kStep = 1.0;
```
`private:` 아래는 모터 **내부 상태**다. 밖에서 직접 건드릴 수 없다.
현재 위치, 목표 위치, 한 걸음 크기(1.0)가 들어 있다. 이름 끝의 `_`는 "내부 변수"라는 표시 관례다.

왜 밖에서 못 건드리게 하는가? 누군가 `motor.position_ = 999;`라고 써 버리면
실제로는 움직이지도 않았는데 위치만 바뀌는 **거짓 상태**가 된다. 장비제어에서 이런 것을 막는 게 매우 중요하다.

## 3. motor.cpp 한 줄씩 읽기

```cpp
Motor::Motor(int id) : id_(id) {}
```
생성자의 실제 내용. `Motor::`는 "Motor 클래스에 속한"이라는 뜻.
`: id_(id)`는 "받은 id를 내부 변수 id_에 넣어라". 본문 `{}`은 비어 있다. 할 일이 그것뿐이기 때문이다.

```cpp
void Motor::moveTo(double target) {
    target_ = target;
}
```
목표를 저장만 한다. 정말 그게 다다.

```cpp
void Motor::update() {
    const double diff = target_ - position_;
    if (std::abs(diff) <= kStep) {
        position_ = target_;
    } else {
        position_ += (diff > 0) ? kStep : -kStep;
    }
}
```
여기가 핵심이다.

1. `diff` = 목표까지 남은 거리. 지금 0에 있고 목표가 3.5면 diff는 3.5.
2. 남은 거리가 한 걸음(1.0) 이하면 → 그냥 목표에 딱 맞춘다.
   (안 그러면 3.5 근처에서 3→4→3→4 하며 영원히 떨릴 수 있다)
3. 아니면 → 목표가 앞쪽(`diff > 0`)이면 +1.0, 뒤쪽이면 -1.0 움직인다.

`(조건) ? A : B`는 "조건이 참이면 A, 아니면 B"라는 짧은 if문이다.

```cpp
bool Motor::isArrived() const {
    return position_ == target_;
}
```
현재 위치가 목표와 같으면 도착. 나머지 두 함수는 그냥 값을 돌려주기만 한다.

## 4. main.cpp 한 줄씩 읽기

```cpp
#include <iostream>
#include "motor.h"
```
`iostream`은 화면 출력용(`std::cout`). `"motor.h"`는 우리가 만든 메뉴판을 가져오는 것.
꺾쇠 `< >`는 시스템 제공, 따옴표 `" "`는 내가 만든 파일. 이렇게 구분한다.

```cpp
int main() {
    Motor motor(1);
    motor.moveTo(3.5);
```
프로그램이 시작되면 `main`부터 실행된다. 1번 모터를 만들고, 3.5로 가라고 목표를 준다.

```cpp
    int tick = 0;
    while (!motor.isArrived()) {
        motor.update();
        ++tick;
        std::cout << "  tick " << tick << ": position = " << motor.position() << '\n';
    }
```
"도착하지 않았으면 계속 반복": 한 걸음 움직이고, 횟수를 세고, 지금 위치를 출력한다.
실제 제어 프로그램의 **제어 루프**를 아주 단순하게 만든 것이다.

머릿속으로 돌려 보면 이렇게 된다.

```
tick 1: position = 1
tick 2: position = 2
tick 3: position = 3
tick 4: position = 3.5    ← 남은 거리 0.5 ≤ 1.0 이라 바로 도착
도착! (4 ticks)
```

## 5. "빌드"는 무엇을 하는가?

사람이 쓴 C++ 코드를 컴퓨터가 실행할 수 있는 파일로 바꾸는 과정이다.
네 단계인데, 지금 꼭 기억할 것은 두 개다.

**컴파일 (compile)**
`.cpp` 파일 **하나씩** 따로 기계어 덩어리(`.o`)로 바꾼다.
이때 `main.cpp`는 `motor.h` 메뉴판만 보고 "moveTo라는 게 있다니까 믿고 쓸게"라고 넘어간다.
레시피(`motor.cpp`)는 보지 않는다.

**링크 (link)**
만들어진 `.o` 덩어리들을 **하나로 붙여서** 실행 파일을 만든다.
이때 "main이 쓴 moveTo가 실제로 어디 있지?" 하고 찾아서 연결한다. 없으면 여기서 에러가 난다.

```
main.cpp ──컴파일──▶ main.o ──┐
                              ├──링크──▶ 실행 파일
motor.cpp ──컴파일──▶ motor.o ─┘
```

그래서 에러도 두 종류다.

- **컴파일 에러**: 문법이 틀렸거나, 메뉴판에 없는 것을 주문했을 때. (예: 세미콜론 빠짐)
- **링크 에러**: 메뉴판엔 있는데 레시피 파일을 안 붙였을 때. 메시지에 `undefined reference`라고 나온다.

CMake는 이 과정을 알아서 해 주는 도구다. `cmake --build build`가 "컴파일하고 링크해 줘"라는 뜻이다.

(참고: 컴파일 앞에 `#include`를 실제 텍스트로 펼치는 **전처리** 단계가 있다.
`g++ -E main.cpp -o main.i`로 결과를 볼 수 있는데, 수만 줄이 나온다. `iostream` 전체가 들어오기 때문이다.)

```cpp
bool Motor::moveTo(double target) {

    target_ = target;
    return ______;       // 성공
}
```

`||`는 "또는"이다.


## 9. 질문과 답

### Q1. `constexpr`가 뭐야?

**한 줄 정의:** "프로그램을 **빌드할 때** 이미 값이 정해지는 상수"라는 표시다.

`motor.h`에 이런 줄이 있다.

```cpp
static constexpr double kStep = 1.0;
```

단어를 하나씩 떼어 보면 이렇다.

- `double kStep = 1.0` : 한 걸음 크기는 1.0이다.
- `constexpr` : 이 값은 빌드할 때 1.0으로 **확정**되고, 절대 바뀌지 않는다.
- `static` : 모터를 10개 만들어도 kStep은 **하나만** 있고 모두가 같이 쓴다. 모터마다 따로 들고 있을 필요가 없는 값이기 때문이다.

**`const`와 뭐가 다른가?**
둘 다 "바꿀 수 없다"는 뜻인데, **언제 값이 정해지느냐**가 다르다.

```cpp
const double a = readSensor();      // OK. 실행 중에 센서를 읽고, 그 뒤로 못 바꿈
constexpr double b = readSensor();  // 에러! 센서 값은 빌드할 때 알 수 없음
constexpr double c = 1.0;           // OK. 1.0은 빌드할 때 이미 알고 있음
```

- `const` = "한 번 정해지면 못 바꾼다" (정해지는 시점은 실행 중이어도 됨)
- `constexpr` = "빌드할 때 이미 정해져 있고, 못 바꾼다" (더 엄격함)

**왜 쓰나?**
장비 코드에는 "절대 바뀌면 안 되는 숫자"가 많다. 한 걸음 크기, 최대 속도, 축 개수 같은 것들이다.
`constexpr`로 적어 두면 누가 실수로 바꾸려 해도 컴파일 에러가 나고, 읽는 사람도 "이건 고정값이구나" 하고 바로 안다.
나중에 안전 범위(0~10)를 넣을 때도 이렇게 쓰면 좋다.

```cpp
static constexpr double kMinPosition = 0.0;
static constexpr double kMaxPosition = 10.0;
```

### Q2. `explicit`: "Motor m = 3; 같은 의도치 않은 자동 변환을 막는다"가 무슨 말?

**먼저 배경:** C++ 컴파일러는 꽤 "친절"하다.
타입이 안 맞으면 혼자서 바꿔 줄 방법을 찾는다.

Motor에는 `Motor(int id)`라는 생성자가 있다. 컴파일러는 이걸 보고 이렇게 생각한다.

> "아, int 하나만 있으면 Motor를 만들 수 있구나. 그럼 int가 필요한 자리에 Motor가 와야 하면, int를 Motor로 **몰래 바꿔 줘도** 되겠네."

그래서 `explicit`가 **없으면** 이런 코드가 에러 없이 통과한다.

```cpp
Motor m = 3;   // 컴파일러가 몰래 Motor(3)을 만들어 줌 → 3번 모터
```

"이게 뭐가 문제야?" 싶을 수 있다. 진짜 문제는 함수에 넘길 때 생긴다.

```cpp
void startMotor(const Motor& motor);   // 모터를 받아서 가동하는 함수

startMotor(3);   // 작성자 의도: "3mm 움직여라"? "3번 모터 켜라"?
```

`explicit`가 없으면 이 코드는 **조용히 통과**한다.
컴파일러가 숫자 3으로 **새 Motor(3번)를 임시로 만들어서** 넘긴다.
실제 장비에 연결된 진짜 모터가 아니라, 방금 만들어진 가짜 모터가 가동되는 것이다.
작성자는 에러가 없으니 잘 됐다고 믿는다. 이런 버그는 찾기가 아주 어렵다.

**`explicit`를 붙이면** 컴파일러에게 "몰래 바꾸지 마. 내가 Motor를 만들겠다고 **분명히 쓴** 경우에만 만들어"라고 말하는 것이다.

```cpp
explicit Motor(int id);

Motor m(3);          // OK. Motor를 만든다고 분명히 씀
Motor m = 3;         // 에러! 몰래 변환 금지
startMotor(3);       // 에러! 숫자 3은 Motor가 아님
startMotor(m);       // OK. 진짜 모터를 넘김
```

`explicit`는 영어로 "명시적인, 분명한"이라는 뜻이다.
"숫자에서 Motor로 바뀌는 건 내가 **분명히 적었을 때만**"이라는 의미로 기억하면 된다.

**규칙:** 인자가 하나인 생성자에는 거의 항상 `explicit`를 붙인다. 붙여서 손해 볼 일은 거의 없다.

#### 직접 확인해 보기 (5분)

1. `main.cpp`의 `main()` 안에 `Motor m2 = 3;`을 한 줄 추가하고 빌드한다. 대략 이런 에러가 난다.
   ```
   error: conversion from 'int' to non-scalar type 'Motor' requested
   ```
   "int를 Motor로 바꾸라고 했는데 그건 안 돼"라는 뜻이다.
2. `motor.h`에서 `explicit`를 지우고 다시 빌드한다. 이번엔 에러 없이 통과한다.
   (경고로 unused variable이 나올 수는 있다.)
3. 확인했으면 `explicit`를 되돌려 놓고, 추가한 줄도 지운다.

### Q3. `const Motor&`는 무슨 뜻? Motor 객체의 주소를 상수로 받는 것?

**절반은 맞다.** 정확히는 "**원본 Motor를 복사하지 않고 그대로 받되, 읽기만 하겠다**"는 뜻이다.
뒤에서부터 읽으면 쉽다.

```
const Motor &
          └─ & : 참조(reference). 원본의 "다른 이름"
   └───── Motor : 무엇의 참조? Motor의
└──────── const : 그 Motor를 바꾸지 않겠다
```

#### `&`는 "주소"가 아니라 "별명"

여기가 헷갈리는 지점이다. `&`는 쓰는 자리에 따라 뜻이 다르다.

```cpp
Motor& ref = motor;   // 타입 옆의 &  → "참조". ref는 motor의 별명
Motor* ptr = &motor;  // 변수 앞의 &  → "주소를 꺼내라". ptr에 주소가 담김
```

- **타입 옆에 붙은 `&`** (`Motor&`) = 참조. 원본의 **다른 이름**이다.
- **변수 앞에 붙은 `&`** (`&motor`) = 주소 연산자. 그 변수가 메모리 어디 있는지 꺼낸다.

같은 기호인데 뜻이 다르다. `const Motor&`는 앞쪽, 즉 **참조**다.

참조는 별명이라고 생각하면 된다. "김동현"을 "동현"이라고 불러도 같은 사람이다.
`ref`를 건드리면 `motor`를 건드리는 것과 완전히 같다. 복사본이 아니다.

(실제로 컴파일러는 참조를 내부적으로 주소로 구현하는 경우가 많다.
그래서 "주소"라고 짐작한 것도 틀린 감각은 아니다. 하지만 코드를 쓸 때는 **별명**으로 생각하는 게 맞다.
포인터처럼 `*`를 붙이거나 nullptr 검사를 할 필요가 없다.)

#### `const`는 "Motor를 바꾸지 않겠다"

`const`는 주소나 참조가 아니라 **Motor 쪽**에 걸린다.
"이 별명으로는 모터를 읽기만 하고, 상태를 바꾸지 않겠다"는 약속이다.

```cpp
void printMotor(const Motor& motor) {
    std::cout << motor.position();   // OK. position()은 const 함수라 읽기만 함
    motor.moveTo(5.0);               // 에러! 목표를 바꾸는 건 상태 변경
}
```

`motor.h`에서 `position() const`처럼 뒤에 `const`를 붙인 함수만 부를 수 있는 이유가 이것이다.
그 `const`가 "이 함수는 읽기만 한다"는 표시였다.

#### 함수에 넘기는 세 가지 방법 비교

```cpp
void a(Motor motor);         // 값: 모터를 통째로 복사해서 받음. 원본과 무관
void b(Motor& motor);        // 참조: 원본을 받음. 바꿀 수 있음
void c(const Motor& motor);  // const 참조: 원본을 받음. 읽기만 함
```

장비에 비유하면 이렇다.

- **a (값)**: 모터의 **설계도를 복사해서** 넘긴다. 복사본을 아무리 움직여도 진짜 모터는 그대로다.
- **b (참조)**: 진짜 모터의 **조종기**를 넘긴다. 받은 쪽이 모터를 움직일 수 있다.
- **c (const 참조)**: 진짜 모터의 **상태 모니터**를 넘긴다. 위치는 볼 수 있지만 조종은 못 한다.

#### 언제 무엇을 쓰나

- 상태를 **보기만** 하는 함수 → `const Motor&` (가장 흔함)
- 모터를 **조작**해야 하는 함수 → `Motor&`
- `int`, `double`처럼 **작은 값** → 그냥 값으로 (`double target`). 복사해도 싸기 때문이다.

Motor 같은 객체를 값으로 넘기면 매번 복사가 일어난다.
게다가 실제 장비 객체라면 "모터가 두 대가 되는" 이상한 상황이 된다. 그래서 객체는 보통 참조로 넘긴다.

#### Q2와 연결: 왜 `startMotor(3)`이 통과했나?

`const Motor&`는 특별한 성질이 하나 있다. **방금 만든 임시 객체도 받을 수 있다.**
그래서 `explicit`가 없으면 컴파일러가 숫자 3으로 임시 Motor를 만들고, 그걸 `const Motor&`에 연결해 버린다.
`explicit`는 그 "임시 Motor 만들기" 단계를 막는 것이다.

#### 직접 확인해 보기 (10분)

`main.cpp`의 `main()` 위에 함수 하나를 추가한다.

```cpp
void printMotor(const Motor& motor) {
    std::cout << "Motor " << motor.id() << " at " << motor.position() << '\n';
}
```

1. `main()` 안 while 루프 다음에 `printMotor(motor);`를 호출해 본다. 위치가 출력되면 성공.
2. `printMotor` 안에 `motor.moveTo(5.0);`을 넣고 빌드해 본다. 에러 메시지를 읽는다.
   (`passing 'const Motor' as 'this' argument discards qualifiers` 비슷한 메시지가 나온다.
   "const로 받은 모터에 상태를 바꾸는 함수를 부르려 했다"는 뜻이다.)
3. 이번엔 `const`를 지우고(`Motor& motor`) 다시 빌드한다. 통과하고, 원본 모터의 목표가 5.0으로 바뀐다.
4. 다 확인했으면 `const`를 되돌린다.

더 자세한 비교 예제는 `02_references_pointers/main.cpp`에 있다.

### Q4. 헤더에는 클래스 모양만, .cpp에 함수 내용을 다 쓰는데, 보통 그렇게 개발하나?

**그렇다. C++에서 가장 일반적인 방식이다.**

- `motor.h` : Motor가 **무엇을 할 수 있는지** (함수 이름, 인자, 반환형, 멤버 변수)
- `motor.cpp` : 그걸 **어떻게 하는지** (함수 본문)

#### 왜 이렇게 나누나?

**이유 1. 빌드가 빨라진다.**
`#include "motor.h"`는 헤더 내용을 그 자리에 **복사해서 붙여 넣는** 것이다.
Motor를 쓰는 .cpp가 20개면, 헤더는 20번 복사되어 20번 컴파일된다.

- `update()` 본문을 **헤더**에 썼다면 → 본문 한 줄만 고쳐도 20개 파일이 전부 다시 컴파일된다.
- `update()` 본문을 **motor.cpp**에 썼다면 → motor.cpp 하나만 다시 컴파일하고 링크하면 끝이다.

작은 예제에서는 차이가 없지만, 장비 소프트웨어처럼 파일이 수백 개가 되면 빌드 시간이 몇 초와 몇십 분으로 갈린다.

**이유 2. 쓰는 사람이 알아야 할 것만 보여 준다.**
Motor를 쓰는 사람은 헤더만 보면 된다. "moveTo로 목표를 주고, update로 움직이고, isArrived로 확인한다."
내부에서 한 걸음을 어떻게 계산하는지는 몰라도 된다. 메뉴판과 레시피를 나눈 이유와 같다.
나중에 `update()` 계산 방식을 바꿔도, 헤더가 그대로면 쓰는 쪽 코드는 손댈 필요가 없다.

**이유 3. 함수 본문이 프로그램 전체에 딱 하나만 있게 된다.**
C++에는 "같은 함수의 본문은 프로그램 전체에 하나만 있어야 한다"는 규칙이 있다.
일반 함수 본문을 헤더에 쓰면, 그 헤더를 include한 .cpp마다 본문이 하나씩 생긴다.
그러면 링크할 때 `multiple definition` 링크 에러가 난다. .cpp에 두면 이런 일이 없다.

#### 예외: 헤더에 본문을 쓰는 경우

**(1) 아주 짧은 함수**
값만 돌려주는 한 줄짜리 함수는 헤더의 클래스 안에 바로 쓰는 경우가 많다.

```cpp
class Motor {
public:
    double position() const { return position_; }   // 클래스 안에 본문을 바로 씀
    int id() const { return id_; }
    ...
};
```

클래스 안에 쓴 함수는 자동으로 `inline` 취급이라 이유 3의 링크 에러가 나지 않는다.
컴파일러가 함수 호출 대신 본문을 그 자리에 바로 넣어 줄 수도 있어서 아주 조금 빨라질 수도 있다.
이 프로젝트에서는 공부를 위해 일부러 전부 .cpp에 나눠 둔 것이다.

**(2) 템플릿 (나중에 배움)**
`std::vector<int>`처럼 타입을 나중에 정하는 코드는 컴파일러가 본문을 보면서 만들어야 해서, 보통 헤더에 전부 쓴다.
`<vector>`, `<map>` 같은 표준 라이브러리 헤더가 거대한 이유다.

**(3) constexpr 값**
`static constexpr double kStep = 1.0;`처럼 빌드할 때 정해지는 값은 헤더에 바로 쓴다.

#### 실무에서 쓰는 기준 (간단 버전)

- 기본은 **헤더에 선언, .cpp에 구현**.
- 한 줄짜리 getter는 헤더에 써도 된다. (팀 규칙을 따른다)
- 헤더에는 꼭 필요한 `#include`만 넣는다. 헤더가 무거우면 그걸 include한 모든 파일이 느려진다.

#### 용어 하나 정리

정확히 말하면 `motor.h`에 있는 건 **클래스 정의**(class definition)이고, 그 안의 함수들은 **선언**(declaration)이다.
`motor.cpp`에 있는 건 **함수 정의**(function definition)다.
"클래스는 헤더에서 정의, 멤버 함수는 헤더에서 선언하고 .cpp에서 정의"라고 말하면 정확하다.
