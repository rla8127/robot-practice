# 06. 복사와 이동 — 학습 노트

> 2주 차 마지막 주제. 05에서 `std::move`로 `unique_ptr`을 "넘겨줬던" 것의 **속사정**을 들여다본다.

---

## 1. 오늘 배울 내용 한 문장

**큰 데이터를 다른 곳으로 넘길 때, 통째로 베끼지(복사) 않고 "소유권만 넘기는(이동)" 방법을 배운다.**

---

## 2. 이 개념이 필요한 이유

### 2-1. 장비 SW는 큰 데이터를 계속 넘긴다

로봇 소프트웨어에서는 이런 흐름이 매 주기마다 일어난다.

```
라이다 드라이버 ──▶ 필터 ──▶ 장애물 인식 ──▶ 경로 계획
   (스캔 데이터 1회 = 거리 값 수천 개)
```

카메라라면 프레임 한 장이 수 MB다. 이걸 단계마다 **통째로 베끼면**:

- 메모리를 새로 받는 데 시간이 든다.
- 수천~수백만 개 값을 하나씩 베끼는 데 시간이 든다.
- 제어 주기(예: 10ms) 안에 처리가 끝나지 않을 수 있다.

그런데 잘 보면, 라이다 드라이버는 데이터를 **넘겨준 뒤에 그 데이터를 다시 쓰지 않는다.**
그럼 베낄 필요 없이 **"이제 이건 네 거야" 하고 넘기기만** 하면 된다. 이게 **이동**이다.

### 2-2. 05에서 이미 본 것

```cpp
auto b = std::move(a);   // unique_ptr 소유권 이동
```

05에서는 "`unique_ptr`은 복사가 안 되니까 이동한다"고만 했다.
오늘은 **이동이 실제로 무슨 일을 하는지**, 그리고 **내 클래스도 이동할 수 있게 만드는 법**을 본다.

---

## 3. 일상적인 비유

**이사하는 상황**을 생각해 보자. 집에 짐이 가득하다.

| 방법 | 하는 일 | 비용 | 원래 집은? |
|---|---|---|---|
| **복사** | 새 집을 하나 더 짓고, 가구를 **똑같이 하나씩 새로 사서** 채운다 | 매우 비쌈 | 그대로 있음 |
| **이동** | 원래 집의 **열쇠와 등기 서류만** 넘겨준다 | 거의 공짜 | 내 손엔 아무것도 없음 (빈손) |

이동은 짐을 하나도 옮기지 않는다. **"이 집은 이제 네 것"이라는 소유권만 넘긴다.**

C++에서 "집"은 힙 메모리고, "열쇠"는 그 메모리를 가리키는 **포인터 하나**다.
포인터 하나 넘기는 건 숫자 하나 베끼는 것만큼 싸다.

---

## 4. 가장 간단한 코드 예제

`Buffer`를 보기 전에, 이미 아는 `std::vector`로 먼저 확인한다. 새 개념은 **"복사 vs 이동"** 하나뿐이다.

```cpp
#include <iostream>
#include <utility>   // std::move
#include <vector>

int main() {
    std::vector<double> scan(1000);              // 라이다 스캔 1회: 거리 값 1000개

    std::vector<double> copied = scan;            // 복사
    std::cout << "복사 후 scan = " << scan.size() << ", copied = " << copied.size() << '\n';

    std::vector<double> moved = std::move(scan);  // 이동
    std::cout << "이동 후 scan = " << scan.size() << ", moved = " << moved.size() << '\n';
}
```

출력:

```
복사 후 scan = 1000, copied = 1000
이동 후 scan = 0, moved = 1000
```

- **복사** 후: `scan`도 1000, `copied`도 1000. 데이터가 **두 벌**이 됐다.
- **이동** 후: `scan`은 0, `moved`는 1000. 데이터는 **여전히 한 벌**이고, 주인만 바뀌었다.

> **잠깐 확인 ①**
> 이동 후 `scan.size()`가 0인 이유를 3절의 비유로 말해 보자. (답: 열쇠를 넘겨줘서 빈손이 됐다)

그럼 `vector`는 속에서 어떻게 이걸 하는 걸까? 그걸 직접 구현해 본 것이 `main.cpp`의 `Buffer`다.

## 5. 코드 한 줄씩 설명 (main.cpp)

### 5-1. Buffer의 모양

```cpp
class Buffer {
    ...
private:
    std::size_t size_;  // 칸 개수
    int* data_;         // 힙에 있는 int 배열의 시작 주소
};
```

- `std::size_t` : **개수나 크기**를 담는 정수 타입이다. 음수가 없다. `vector.size()`도 이 타입을 돌려준다.
- `int* data_` : 힙에 있는 int 배열의 **시작 주소**를 담는 포인터다. (02)

`Buffer`는 `std::vector<int>`를 아주 단순하게 흉내 낸 것이다. 실무에서는 이렇게 만들지 않는다. (11절 Rule of Zero)
**동작 원리를 보려고** 일부러 직접 만든 것이다.

### 5-2. 생성자와 소멸자

```cpp
explicit Buffer(std::size_t size) : size_(size), data_(new int[size]{}) {
    std::cout << "  생성자 (size=" << size_ << ")\n";
}

~Buffer() {
    delete[] data_;
}
```

새로 나온 문법을 하나씩 떼어 본다.

| 조각 | 뜻 |
|---|---|
| `new int[size]` | 힙에 int를 `size`개 **배열로** 만들고, 시작 주소를 돌려준다 |
| `{}` (뒤에 붙은 것) | 배열의 모든 칸을 **0으로** 채운다. 없으면 아무 값(쓰레기 값)이 들어 있다 |
| `delete[] data_` | `new[]`로 만든 **배열**을 돌려준다. 배열은 `delete`가 아니라 **`delete[]`**로 지운다 |

생성자에서 메모리를 얻고, 소멸자에서 돌려준다. **04의 RAII 그대로**다.

### 5-3. 복사 생성자 — 깊은 복사

```cpp
Buffer(const Buffer& other) : size_(other.size_), data_(new int[other.size_]) {
    for (std::size_t i = 0; i < size_; ++i) {
        data_[i] = other.data_[i];
    }
    std::cout << "  복사 생성자 (" << size_ << "개 복사)\n";
}
```

**언제 불리나?** `Buffer b = a;`처럼 **이미 있는 `a`를 본떠서 새 `b`를 만들 때**.

| 조각 | 뜻 |
|---|---|
| `Buffer(...)` | 이름이 클래스와 같고 반환형이 없다 → **생성자**다 |
| `const Buffer& other` | 원본을 복사 없이 받되(`&`), 원본은 건드리지 않겠다(`const`). (02) |
| `other.size_` | `size_`는 `private`인데 `other` 것에 접근할 수 있다. **같은 클래스 코드 안에서는** 다른 객체의 `private`도 볼 수 있다 |
| `data_(new int[other.size_])` | 원본과 **다른, 새** 메모리를 받는다. ← 핵심 |
| `for` 반복문 | 칸마다 값을 하나씩 베낀다. 1000칸이면 1000번 |

이렇게 **메모리까지 새로 만들어서 내용을 베끼는 것**을 **깊은 복사(deep copy)**라고 한다.

> **왜 새 메모리를 받아야 할까?** `data_(other.data_)`처럼 **주소만** 베끼면 어떻게 될까?
> → 9절 해 보기 3에서 직접 확인한다. (힌트: 04의 "OFF가 두 번")

### 5-4. 이동 생성자 — 포인터만 옮기기

```cpp
Buffer(Buffer&& other) noexcept : size_(other.size_), data_(other.data_) {
    other.size_ = 0;
    other.data_ = nullptr;
    std::cout << "  이동 생성자 (포인터만 옮김)\n";
}
```

**언제 불리나?** `Buffer c = std::move(a);`처럼 **"곧 버려질 객체"로 새 객체를 만들 때**.

여기에 처음 보는 문법이 두 개 있다.

#### (1) `Buffer&&` — 버려질 객체만 받는 참조

`&`가 **두 개**다. 02에서 배운 참조(`&` 하나)와 다르다.

| 쓰는 법 | 이름 | 받을 수 있는 것 | 안의 자원을 가져가도 되나? |
|---|---|---|---|
| `const Buffer&` | const 참조 | 아무거나 (이름 있는 것, 임시 객체 모두) | ❌ 읽기만 |
| `Buffer&&` | **rvalue 참조** | **곧 버려질 것**만 | ⭕ 가져가도 됨 |

"곧 버려질 것"에는 두 종류가 있다.

- **이름 없는 임시 객체** : `Buffer(10)`처럼 만들자마자 `;`에서 사라지는 것 (03)
- **`std::move(x)`로 표시한 것** : "x는 이제 안 쓸 테니 가져가도 돼"라고 내가 허락한 것

C++ 용어로는 이런 걸 **rvalue**(오른값)라고 부르고, 이름이 있어서 계속 쓸 수 있는 것을 **lvalue**(왼값)라고 부른다.
이름은 어렵지만, 지금은 **"계속 쓸 것(lvalue)"과 "버려질 것(rvalue)"**으로 기억하면 충분하다.

#### (2) `noexcept` — 예외를 던지지 않겠다는 약속

`noexcept`는 "**이 함수는 절대 예외를 던지지 않는다**"는 표시다.
이동 생성자는 포인터 몇 개만 바꾸니까 실패할 일이 없다. 그래서 이 약속을 붙인다.

이게 왜 중요한지는 9절 해 보기 4에서 `vector`와 함께 확인한다.

#### (3) 본문: 원본을 비운다

```cpp
other.size_ = 0;
other.data_ = nullptr;
```

이 두 줄이 **반드시** 있어야 한다. 없으면 어떻게 될까?

```
나(c)의 data_     ──┐
                    ├──▶ [힙 1000칸]
원본(a)의 data_   ──┘
```

둘 다 같은 메모리를 가리킨다. 나중에 `a`와 `c`가 소멸하면 **같은 메모리를 두 번 `delete[]`** → 프로그램 충돌.
그래서 원본의 포인터를 `nullptr`로 바꿔서 **"이 메모리는 이제 내 것이 아니다"**를 분명히 한다.

`nullptr`을 `delete[]` 하면 **아무 일도 일어나지 않는다.** 그래서 비워진 `a`는 안전하게 소멸할 수 있다.

> **잠깐 확인 ②**
> 복사 생성자와 이동 생성자의 초기화 리스트에서 `data_(...)` 부분만 비교해 보자. 각각 괄호 안에 무엇이 들어 있나?
> (복사: `new int[other.size_]` = 새 메모리 / 이동: `other.data_` = 원본의 주소)

### 5-5. 대입 연산자는 막아 두었다

```cpp
Buffer& operator=(const Buffer&) = delete;
Buffer& operator=(Buffer&&) = delete;
```

**생성**과 **대입**은 다르다. `=` 기호가 같아서 아주 헷갈린다.

```cpp
Buffer b = a;   // 생성. b가 "새로" 만들어진다 → 복사 생성자
Buffer e(5);
e = a;          // 대입. 이미 있는 e에 "덮어쓴다" → 복사 대입 연산자 (operator=)
```

**구분법:** 줄 맨 앞에 **타입 이름(`Buffer`)이 있으면 생성**, 없으면 대입이다.

대입은 "원래 갖고 있던 메모리를 먼저 돌려주기" 같은 일이 더 필요해서 예제를 짧게 하려고 `= delete`(04)로 막아 두었다.

### 5-6. main()

```cpp
Buffer a(1000);
Buffer b = a;              // 복사 생성자
Buffer c = std::move(a);   // 이동 생성자
```

**`std::move`는 아무것도 옮기지 않는다.** 이게 가장 많이 오해하는 부분이다.

- `std::move(a)` : `a`에 **"버려도 됨" 딱지를 붙이기만** 한다. 그 자체로는 아무 일도 안 일어난다.
- 그 딱지 덕분에 컴파일러가 `Buffer&&`를 받는 **이동 생성자를 고른다.**
- 실제로 포인터를 옮기는 건 **이동 생성자**다.

```
std::move(a)  ──▶  "a는 rvalue"  ──▶  컴파일러가 이동 생성자 선택  ──▶  이동 생성자가 포인터를 옮김
 (딱지 붙이기)                        (고르기)                        (실제 작업)
```

```cpp
Buffer makeBuffer() {
    Buffer b(1000);
    return b;
}
Buffer d = makeBuffer();   // "생성자"만 한 번 출력된다
```

함수 안의 `b`를 돌려주면 복사나 이동이 일어날 것 같지만, 실제로는 **둘 다 안 일어난다.**
컴파일러가 처음부터 `d`의 자리에 `b`를 **바로 만들기** 때문이다. 이걸 **복사 생략(copy elision)**이라고 하고,
이름 있는 변수를 돌려줄 때의 생략을 특히 **NRVO**라고 부른다. (해 보기 5에서 이걸 끄고 확인한다)

→ 그래서 **함수가 큰 객체를 돌려줄 때 `return std::move(b);`라고 쓰지 않는다.** 그냥 `return b;`가 가장 빠르다.

```cpp
std::vector<Buffer> buffers;
buffers.reserve(2);
buffers.push_back(Buffer(10));   // 생성 + 이동
buffers.emplace_back(20);        // 생성만
```

| 함수 | 넘기는 것 | 일어나는 일 |
|---|---|---|
| `push_back(Buffer(10))` | **완성된 객체** | 밖에서 임시 `Buffer` 생성 → vector 안으로 **이동** |
| `emplace_back(20)` | 객체를 만들 **재료** | vector가 자기 자리에서 `Buffer(20)`을 **바로 생성** |

`reserve(2)`는 "원소 2개 들어갈 자리를 **미리** 잡아 둬"라는 뜻이다. 원소를 만들지는 않는다. (이유는 해 보기 4)

## 6. 메모리·객체 상태 변화 시각화

`main()`의 앞부분을 한 줄씩 실행하며 메모리가 어떻게 변하는지 본다. 주소는 이해를 위해 지어낸 숫자다.

**① `Buffer a(1000);`**

```
a [size_=1000, data_=0x100] ──▶ 0x100: [0][0][0]...(1000칸)
```

**② `Buffer b = a;`** — 복사 생성자

```
a [size_=1000, data_=0x100] ──▶ 0x100: [0][0][0]...(1000칸)
b [size_=1000, data_=0x900] ──▶ 0x900: [0][0][0]...(1000칸)   ← 새 메모리 + 1000번 베낌
```

힙에 1000칸짜리가 **두 개**. 서로 완전히 독립이다. `b`를 고쳐도 `a`는 안 바뀐다.

**③ `Buffer c = std::move(a);`** — 이동 생성자

```
a [size_=0,    data_=nullptr]                                    ← 빈손
b [size_=1000, data_=0x900] ──▶ 0x900: [0][0][0]...(1000칸)
c [size_=1000, data_=0x100] ──▶ 0x100: [0][0][0]...(1000칸)   ← a가 갖던 바로 그 메모리
```

새 메모리는 **하나도 안 생겼다.** `0x100`의 주인이 `a`에서 `c`로 바뀌었을 뿐이다.

**④ `main()`이 끝날 때** — 역순으로 소멸 (03)

```
c 소멸 → delete[] 0x100   ✔
b 소멸 → delete[] 0x900   ✔
a 소멸 → delete[] nullptr  (아무 일도 안 함) ✔
```

모든 메모리가 **정확히 한 번씩** 돌려받았다.

## 7. 비슷한 개념과 차이점

### 7-1. 복사 vs 이동 vs 참조

셋 다 "다른 곳에서 이 데이터를 쓰게 한다"는 점은 같다. 차이를 표로 비교한다.

| | 복사 `Buffer b = a;` | 이동 `Buffer c = std::move(a);` | 참조 `Buffer& r = a;` |
|---|---|---|---|
| 새 객체가 생기나 | ⭕ | ⭕ | ❌ (별명일 뿐, 02) |
| 새 힙 메모리를 받나 | ⭕ | ❌ | ❌ |
| 비용 | 데이터 크기만큼 | 포인터 몇 개 | 0 |
| 원본은? | 그대로 | **비워짐** | 그대로 (같은 것) |
| 주인은 몇 명? | 각자 한 벌씩 2명 | 1명 (넘겨받은 쪽) | 1명 (원본) |
| 언제 쓰나 | 독립된 사본이 필요할 때 | 원본을 더 안 쓸 때 | 잠깐 빌려 쓸 때 |

**선택 순서:** 빌려 쓰기만 하면 **참조**. 넘겨줘야 하는데 원본을 더 안 쓰면 **이동**. 둘 다 아니면 **복사**.

### 7-2. 깊은 복사 vs 얕은 복사

| | 깊은 복사 (deep copy) | 얕은 복사 (shallow copy) |
|---|---|---|
| 베끼는 것 | 포인터가 **가리키는 내용**까지 | **포인터(주소)만** |
| 결과 | 메모리 두 벌, 서로 독립 | 메모리 한 벌을 **둘이 동시에** 가리킴 |
| 소멸할 때 | 각자 자기 것만 지움 ✔ | 같은 메모리를 **두 번** 지움 ✘ 충돌 |

포인터 멤버가 있는 클래스를 컴파일러에게 그냥 복사하라고 맡기면 **얕은 복사**가 된다. (해 보기 3)

### 7-3. 이동 vs unique_ptr 이동 (05와 연결)

05의 `auto b = std::move(a);`(unique_ptr)도 **오늘 본 이동 생성자**가 한 일이다.
`unique_ptr`의 이동 생성자도 안에서 "포인터 가져오기 → 원본을 `nullptr`로"를 한다. 그래서 이동 후 `a`가 비어 있었다.

| | `unique_ptr` | `Buffer` |
|---|---|---|
| 복사 | `= delete` (주인은 한 명만) | 깊은 복사 허용 |
| 이동 | 허용 | 허용 |

`unique_ptr`은 "**복사는 막고 이동만**" 열어 둔 클래스, `Buffer`는 "**둘 다**" 열어 둔 클래스다.
04의 `MotorPowerGuard`는 둘 다 막혀 있다. (전원은 베낄 수도 넘길 수도 없게 만들었다)

### 7-4. 직접 만들어야 하는 함수 5개 (Rule of Five / Rule of Zero)

클래스에는 "객체를 만들고·베끼고·옮기고·지우는" 특별한 함수가 5개 있다.

| 함수 | 모양 | 언제 불리나 |
|---|---|---|
| 소멸자 | `~Buffer()` | 객체가 사라질 때 |
| 복사 생성자 | `Buffer(const Buffer&)` | `Buffer b = a;` |
| 복사 대입 | `operator=(const Buffer&)` | `b = a;` |
| 이동 생성자 | `Buffer(Buffer&&)` | `Buffer c = std::move(a);` |
| 이동 대입 | `operator=(Buffer&&)` | `c = std::move(a);` |

- **Rule of Five (5의 규칙)** : 이 중 **하나라도** 직접 만들었다면 (= 포인터 같은 자원을 직접 관리한다면) **나머지 넷도** 어떻게 할지 정해야 한다.
- **Rule of Zero (0의 규칙)** : 애초에 자원을 직접 관리하지 말고, `std::vector`, `std::unique_ptr` 같은 **이미 잘 만들어진 RAII 멤버**를 쓰자. 그러면 **하나도 직접 만들 필요가 없다.** 컴파일러가 알아서 올바르게 만들어 준다.

**실무의 기본은 Rule of Zero다.** `Buffer`처럼 직접 만드는 건 원리를 배울 때와, 하드웨어 핸들처럼 표준 라이브러리에 없는 자원을 감쌀 때뿐이다.

## 8. 장비제어 SW 실전 예제

라이다 스캔을 받아서 처리 큐에 넣는 상황이다.

```cpp
#include <iostream>
#include <utility>
#include <vector>

// 한 번의 스캔 = 각도별 거리 값 묶음
struct LidarScan {
    int sequence;                  // 몇 번째 스캔인지
    std::vector<double> ranges;    // 거리 값들 (m)
};

// 드라이버가 스캔 한 번을 읽어 온다고 가정
LidarScan readScan(int seq) {
    LidarScan scan{seq, std::vector<double>(3600, 1.0)};  // 0.1도 간격 → 3600개
    return scan;                   // 복사 생략 (std::move 쓰지 않음)
}

int main() {
    std::vector<LidarScan> processQueue;

    for (int seq = 1; seq <= 3; ++seq) {
        LidarScan scan = readScan(seq);
        // ... 여기서 scan을 잠깐 검사할 수 있다 ...
        processQueue.push_back(std::move(scan));   // 큐에 넘긴다. 3600개를 베끼지 않는다.
        // scan은 이제 비어 있다. 다시 쓰지 않는다.
    }

    std::cout << "큐에 쌓인 스캔: " << processQueue.size() << "개\n";
    std::cout << "첫 스캔의 거리 값 개수: " << processQueue[0].ranges.size() << '\n';
}
```

**여기서 볼 것**

- `LidarScan`에는 소멸자도, 복사/이동 생성자도 **직접 만든 게 하나도 없다.** 그런데 이동이 된다.
  멤버가 `int`와 `std::vector`뿐이라 컴파일러가 이동 생성자를 **알아서 만들어 준다.** 이게 **Rule of Zero**다.
- `push_back(std::move(scan))` : 루프가 돌 때마다 `scan`은 새로 만들어지고, 다 쓴 뒤에 큐로 **넘겨진다.** 원본을 다시 쓰지 않으니 이동이 딱 맞다.
- `return scan;` : 함수에서 돌려줄 때는 `std::move`를 **쓰지 않는다.** (5-6절 복사 생략)

> **잠깐 확인 ③**
> `push_back(std::move(scan))`을 `push_back(scan)`으로 바꾸면 프로그램 결과는 같을까? 무엇이 달라질까?
> (결과 출력은 같다. 하지만 매 루프마다 거리 값 3600개가 **복사**된다. 느려질 뿐 틀리지는 않는다.)

```
push_back 후:    vector 자리 [ Buffer(10) ]                  ← 자리가 딱 1개
emplace_back:    자리가 부족! → 2칸짜리 새 자리를 받는다
                 새 자리 [ ______ ][ Buffer(20) ]  ← 기존 원소를 새 자리로 "이동"
                 옛 자리는 돌려준다
```

`vector`는 자리가 모자라면 **더 큰 자리를 새로 받고, 기존 원소를 전부 옮긴다.** 이걸 **재할당(reallocation)**이라고 한다.
`reserve`로 미리 자리를 잡으면 이 이동이 사라진다.

**(2)** 이번엔 `reserve`를 주석 처리한 **상태 그대로**, 이동 생성자의 `noexcept`도 지우고 실행한다.

마지막 줄이 `이동 생성자`에서 무엇으로 바뀌나?

<details>
<summary>왜 그럴까? (먼저 생각해 본 뒤 펼친다)</summary>

`vector`가 원소를 옮기다가 **중간에 예외가 나면**, 이미 옮긴 원소는 원래 자리에서 비워졌으니 되돌릴 수 없다. 데이터가 망가진다.
그래서 `vector`는 "이동이 **절대 실패하지 않는다(`noexcept`)**고 약속한 경우에만 이동하고, 아니면 안전하게 **복사**한다."
복사는 원본이 그대로 남아 있으니 실패해도 되돌릴 수 있기 때문이다.

→ **이동 생성자에는 `noexcept`를 붙인다.** 안 붙이면 `vector` 안에서 조용히 복사로 바뀐다.

</details>

## 11. 핵심 정리

- **복사**는 데이터를 두 벌로 만든다. **이동**은 한 벌 그대로 **주인만 바꾼다.**
- 이동은 "원본의 포인터를 가져오고, 원본은 비우는 것"이다. 그래서 빠르다.
- `std::move`는 **딱지 붙이기**일 뿐이다. 실제 이동은 **이동 생성자**가 한다.
- `Buffer&&`(rvalue 참조)는 **곧 버려질 것**만 받는다. 그래서 안의 자원을 가져가도 된다.
- 이동된 객체는 **비어 있지만 유효하다.** 소멸은 안전하고, 새 값을 넣어 다시 쓸 수는 있다. 하지만 남은 값을 기대하고 읽으면 안 된다.
- 함수에서 돌려줄 때는 `return x;`. `return std::move(x);`는 오히려 복사 생략을 막는다.
- **기본은 Rule of Zero**: 자원은 `vector`, `unique_ptr`에 맡기고, 5개 특별 함수는 직접 만들지 않는다.

## 12. 특히 주의할 점

1. **이동한 뒤의 원본을 쓰지 말 것.** `std::move(scan)` 다음에 `scan[0]`을 읽는 코드는 컴파일은 되지만 틀린 코드다. (05 해 보기 2의 충돌과 같은 종류)
2. **`std::move`를 붙여도 이동이 안 될 수 있다.** 이동 생성자가 없으면 조용히 복사된다. (해 보기 2)
3. **`const` 객체는 이동이 안 된다.** `const Buffer a(10); Buffer c = std::move(a);`는 복사가 된다. 이동은 원본을 **비워야** 하는데, `const`는 원본을 못 바꾸게 하기 때문이다.
4. **포인터 멤버를 직접 관리하면 5개 함수를 모두 신경 써야 한다.** 하나라도 빠지면 얕은 복사 → 두 번 해제. (해 보기 3)
5. **이동 생성자에는 `noexcept`.** 안 붙이면 `vector` 재할당 때 복사로 바뀐다. (해 보기 4)
6. **`Buffer b = a;`는 대입이 아니라 생성이다.** `=`가 보여도 줄 맨 앞에 타입이 있으면 생성자가 불린다.
